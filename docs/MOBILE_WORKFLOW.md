# Работа с Animator с телефона

## Рекомендуемый режим

На телефоне использовать браузерный режим проекта. Tauri, Rust и Android SDK нужны только для нативной сборки, а не для обычного редактирования и проверки интерфейса.

## Передача файлов

- хранить модели в GLB, анимации в `animation.json`, проекты в `.rcanim`;
- использовать Google Drive для резервных копий исходников;
- использовать GitHub для версий исходного кода;
- не отправлять большие бинарные модели в каждый commit без необходимости;
- давать ИИ ссылку на конкретный файл и краткое описание ожидаемого изменения.

## Минимальный цикл с телефона

1. Открыть веб-preview Animator.
2. Импортировать небольшой GLB-файл.
3. Проверить скелет и embedded animations.
4. Экспортировать небольшой `animation.json` для проверки Blender bridge.
5. Создать issue или commit с описанием: файл, проблема, ожидаемый результат.
6. Попросить ИИ сначала показать diff, затем собрать проект.

## Ограничения телефона

- большие FBX/GLB могут не загрузиться из-за памяти браузера;
- для preview использовать модели до разумного размера и уменьшенное число текстур;
- не запускать нативные Android/iOS builds с телефона без отдельной облачной среды;
- при зависании закрыть preview и открыть его заново, не создавая повторные импорты;
- исходный файл всегда сохранять отдельно.

## Сообщение для ИИ

```text
Я работаю с телефона. Не требуй локальной установки Rust или Android SDK для обычного preview. Сделай изменения в отдельной ветке, показывай краткий diff, используй GLB/JSON, не перезаписывай исходные модели и после изменений запусти npm run build и npm run lint.
```
